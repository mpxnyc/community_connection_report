F.1 Person place network mapper

We designed, tested and implemented a survey tool we call the MPX NYC Person-place network mapper. We designed the tool to solve practical and ethical issues related to the collection of sensitive spatial data in the context of an annonymous survey. Practically, we were interested in collecting data on locations participants visited and possibly had group sex in, but understood that we would not collect useful data if we collected markers like address or zip code using usual survey methods. Ethically, we were aimed to collect a data set that would limit the risk of identifying survey participants through the locations and other data disclosed through the survey.

F.1.1 Place mapping

Though the investigator team doubted that participants would remember addresses or zip codes of places they visited, we thought that they might remember landmarks, cross-streets, neighborhood names, subway stations names, and other markers New Yorkers use to navigate the city so we used the Google maps interface and API.

The MPX NYC Person-Place Network Map question displays a map with detailed geographic information including place names, roads, and neighborhood names. It includes a search bar as well as other navigation tools usually found on a google maps display (see Figure F.1).

To collect anonymous information on locations, first the participant is prompted to identify places of a certain type by tapping on the map. For instance, the first Network Map question asks participants to identify their primary residence. Once they select one, they are able to move onto the next question.

The Network Map also allows researchers to elicit a collection of locations. For instance, we ask participants to identify all the places they have had physical or sexual contact in a group setting. Each time the participant taps the map, a marker appears where they tapped, and a pop-up window asks questions about the most recently identified location. In our study, participants were asked if they had sexual contact at the location and to select the type of location it is from a closed list of options.

F.1.2 Link tracing

We designed a system for anonymously building a referral network

At the start of the survey, the participant is given an identifier image showing a unique combination of words and a QR code. They are prompted to save the image of their identifier card.

Near the end of the survey, the participant is prompted to share the survey with friends with a share button on screen. The share button opens the participant’s device’s native share menu and allows them to edit and share a pre-written invitation to the survey with a unique URL.

If a contact of the participant’s uses the url, an edge will be added between their node and the original participant’s node

Say an new participant takes the survey and shares it with somebody who has already taken the survey (an old participant)

The old participant would go to the url and be prompted to upload their identifier card or to enter the combination of words on the card in a text field. An edge would be added between the new and old participants’ nodes in the graph database

F.1.3 Implementation

Rationale

Collecting spatial coordinates would increase the risk of accidentally identifying people by, for instance, capturing the exact coordinate of a college dormitory as a participant’s residence, or capturing the exact coordinates of a federal government office as a venue for sexual contact in a group setting. In both these examples, it becomes easier to narrow down the identity of participants using the location and the particiapnts’ characteristics as recorded in survey data.

Continuation

The front end of the MPX NYC Person-Place Network Mapper was developed as a single-page web application using the React/NextJS framework (Vercel 2024) with visual design based on the MPX NYC style guide. The back end was a custom-built neo4j graph database (Neo4j 2024). Along with the Network Map question format, the instrument allows the use of standard survey question formats (multiple choice, single choice, text field etc.).

Data flow

  • Front end interface in Next.js hosted on Vercel

    • takex a JSON file for the content of questions, text prompts

    • parses URL for referrer identifier (if any), and survey language

    • requests a public identifier from the API - the API returns a new public identifier. a unique combination of words.

    • shows unique public identifier and a QR code of the public identifier to participant, prompting participant to save the image on their device

    • for person-place network mapper data, front end queries a government database to transform spatial coordinates into census tract identifiers

    • returns a JSON object using the API

  • API on XYZ

    • receives request for an identifier

      • generates a public identifier (described above) paired with a private identifier in the form of uid.

      • Returns public identifer to front end

      • Saves public identifer / private identifer pair in an identifier table in a secure database, separate from study data base

    • receives study data from front end

      • transforms public identifier to private identifers by querying the identifier table

      • sends data to graph data base

    • receives confirmation of link

      • transforms public identifier to private identifers by querying the identifier table

      • send data on the new edge to graph data base

  • graph data base

    • hosted on a cloud server platform

    • designed to represent survey data as one giant graph (see data graph)

    • uses a query language that uses the structure of the graph to simplify complex queries

    • use script or manual entry to declare node types, edge types, and node and edge attribute data

To ensure participant anonymity, the survey tool coarsens spatial data to the census tract level before sending them to the study database. Census tracts are non-overlapping spatial units that partition the United States into areas ranging from \(2500\) to \(8000\) in population size (US Census 2022). This is done through The Federal Communications Commission API (FCC 2022) which receives longitude-latitude coordinates from the survey instrument, and returns census block identifiers, which are transformed to census tract identifiers by truncating the last X digits. [CITATION] It is only after spatial data are transformed that they are transmitted to the study database (backend).
